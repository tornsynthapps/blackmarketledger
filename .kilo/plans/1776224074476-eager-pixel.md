# Plan: New Userscript with Event-Based Sync

## Goal

Refactor legacy userscript to use event-based listener instead of polling. BML website sends cost-basis via postMessage when refreshed.

---

## 1. Userscript Structure

Create `userscript/` folder with modular files:

```
userscript/
├── bml.user.js          # Main entry, metadata, build concatenates others
├── core.js             # Utilities, constants, debug logging
├── styles.js           # CSS strings (GM_addStyle)
├── torn-bazaar.js      # Torn bazaar rendering logic
├── bml-listener.js     # NEW: postMessage listener for BML sync
└── build.mjs          # Build script to concatenate into single .user.js
```

---

## 2. Key Changes

### A. bml-listener.js (NEW)

- Listen for `BML_EXTENSION_REQUEST` message type `COST_BASIS_UPDATE`
- When received, extract cost-basis data from payload
- Store via `GM_setValue(SYNCED_DATA_KEY, data)`
- Trigger bazaar row refresh
- Show toast notification

### B. BML Website Updates

Add new message type in `lib/old/bmlconnect.ts`:

```ts
| "COST_BASIS_UPDATE"
```

Send message when transactions updated in `store/useJournal.ts`:

```ts
window.postMessage(
    {
        type: "BML_EXTENSION_REQUEST",
        message: {
            type: "COST_BASIS_UPDATE",
            payload: { inventory: calculatedInventory },
        },
    },
    "*"
);
```

### C. torn-bazaar.js

No changes to bazaar rendering - just receives data from listener instead of polling.

### D. build.mjs

Simple esbuild/concat to stitch modules into single userscript with proper header injection.

---

## 3. Data Flow

```
User clicks "Refresh" in BML App
  → useJournal calculates cost basis
  → postMessage with COST_BASIS_UPDATE
  → Userscript receives message
  → GM_setValue stores data
  → triggerRefresh() re-renders bazaar rows
```

vs OLD: polling every 15s regardless of actual changes.

---

## 4. Implementation Steps

1. Add `COST_BASIS_UPDATE` to bmlconnect.ts message types
2. Modify useJournal.ts to broadcast on saveTransactions
3. Create userscript/ folder structure
4. Create styles.js, core.js, torn-bazaar.js, bml-listener.js
5. Create build.mjs concatenator
6. Build final userscript
7. Test against Torn bazaar page

---

## 5. Confirmed Requirements (User Answered)

- **Data Format**: Pre-calculated avgCost as `{itemName: avgCost}` - same format legacy uses
- **Sync Trigger**: Broadcast on every `saveTransactions()` call in useJournal
- **Polling**: REMOVED - event-only listener
